# Dataset card — W1 real-audio data engine

## Purpose

This data engine supplies real guitar audio and labels for the W1
pseudo-labeling / student-training workstream. It is **not** a public dataset
release. Audio stays gitignored; only the manifest, scripts, and licence
audit are committed.

### Pseudo-label candidates

`1,173 unlabeled + 264 weak = 1,437` tracks are available for the W1 teacher
pipeline. The G1 gate (≥1,000 pseudo-labeled tracks) is therefore achievable.
The full run is CPU-viable; a sharded CPU pass completed on 2026-11-04
(see “Full CPU run result” below).

## Splits

- **GuitarSet**: `backend/data/manifests/split_policy.json`
  (players 00/01/02/04 = train, 03 = test, 05 = val).
- **All other sources**: deterministic SHA-256 split with salt
  `harmoniq-w1-v1` (80% train / 10% val / 10% test).
- **Eval holdout protection**: any W1 track whose audio appears in the W0
  evaluation manifest inherits that track's split. A test/val eval track can
  never land in W1 `train`.
- Changing the salt intentionally re-splits the data; bump the manifest id
  when you do.

## Label provenance

| Label status | Meaning |
| --- | --- |
| `human` | Dataset annotation (JAMS, MIDI, or chord timeline) |
| `weak` | Crawl/label metadata, not expert-verified |
| `teacher` | Produced by the W1 teacher with confidence filtering |
| `none` | No labels yet; pseudo-label candidate |

## Confidence filtering

The W1 teacher pipeline filters windows by chord-event confidence from the
MT3 chord decoder (template coverage). Windows below `--min-chord-confidence`
(default 0.6) are dropped. MT3 note confidence is currently a `0.9`
placeholder, so note labels inherit the chord-time confidence rather than a
native per-note probability. W5 measured this chord-template confidence at
pooled ECE 0.7281 on 526 tracks; the 0.9–1.0 bin is only 21.9% accurate.
Note-level calibration remains blocked on a native MT3 confidence field.

## Cross-stem augmentation

`backend/scripts/augment_w1.py` implements a cross-stem-style augmentation:
a guitar-only track (GuitarSet `_solo` mix) is mixed with a background track
(RWC-P full mix) at a configurable low gain, keeping the guitar track's
labels. This approximates guitar-stem + accompaniment mixing without a
Demucs pass over every track.

True Demucs stem-swap augmentation (guitar stem A + bass/drums/piano/other
from B) is deferred: it requires a stem cache for the training corpus, which
is a W3-scale compute job. This is an explicit rejection with evidence, not a
silent omission.

## Partial labels / multi-channel decoding

Every track records `label_channels` (`chord`, `solo`). Tracks with chord-only
labels (RWC-P, YouTube crawl) are marked accordingly so the student's solo
head can mask those losses.

Full multi-channel teacher decoding (YourMT3+ style) is deferred to W2/W3:
stock MT3 is single-channel and has no per-channel program masking. W1
implements the label-channel mask that the student training will consume.

## Contamination rules

- Eval test/val audio is excluded from W1 `train` (verified by path overlap).
- Guitar-TECHS `directinput` and `micamp` perspectives share a split so the
  same performance cannot leak across train/test.
- RWC-P is evaluation-only in the public release; its audio is not
  redistributed.

## Known limitations

- IDMT raw clips include single notes, scales, and technique exercises. Many
  will produce few or no chord labels; the pseudo-label report records
  retention rather than assuming every clip is usable.
- Live, home, and kora/mbira OOD recordings are not bundled. Use
  `docs/eval/external_recordings.md` to ingest local recordings;
  unannotated tracks are qualitative and unscored.
- The YouTube crawl labels are weak and its audio is subject to YouTube ToS;
  do not redistribute it.
- MT3 event confidence is a placeholder (`0.9`), so teacher confidence
  filtering currently relies on the chord decoder's template coverage.

## Reproduction

```bash
cd backend

# 1. (optional) refresh the W0 eval manifest when audio/splits change
python scripts/build_eval_manifest.py

# 2. One command: rebuild the W1 data manifest
#    (on a clean checkout the committed docs/eval/amt_manifest.json exists)
python scripts/build_w1_manifest.py

# 3. Smoke pseudo-label 5 unlabeled tracks (CPU-friendly)
python scripts/pseudo_label_w1.py --limit 5 --min-chord-confidence 0.6

# 4. Cross-stem augmentation smoke (GuitarSet solo + RWC-P background)
python scripts/augment_w1.py --limit 2
```

## W5 calibration corpus (2026-11-11)

W5 reused the W0 manifest and the staged W2/W3 volumes to calibrate
chord-template confidence. Coverage: **526 / 705 tracks** (GuitarSet 360,
IDMT 129, EGSet12 12, Guitar-TECHS 10, RWC-P 15). The remaining 179
Guitar-TECHS/RWC-P tracks were not present on the volumes; this is a
documented coverage gap. The pooled result is ECE **0.7281**, mean
confidence **0.9307**, accuracy **0.2026**. See
[`../audit/amt/w5_calibration.md`](../audit/amt/w5_calibration.md) and
[`w5_cloud_runbook.md`](w5_cloud_runbook.md).

The committed per-source reports (`docs/audit/amt/w5_eval_mt3-*.json`) make
the calibration table reproducible without audio or GPUs. The
recording-quality section requires the local audio.

## Smoke result (2026-11-04)

Command:

```bash
cd backend
python scripts/pseudo_label_w1.py \
  --limit 10 --source idmt_smt_guitar --category music \
  --report ../docs/audit/amt/w1_pseudo_label_report.json
```

Result: **10/10 tracks labeled**, **42/52 windows kept** (80.8% retention),
but only **8 non-N chord windows**. The MT3 chord decoder labels most
dataset4 music windows as no-chord. This is a real teacher-quality finding,
not a pipeline bug: it matches the W0 chord-accuracy and ECE results and is
the primary motivation for W2 teacher selection. Do not interpret the W1
smoke as evidence that MT3 pseudo-labels are sufficient for the student.

The full ≥1,000-track run completed on CPU (sharded):

```bash
python scripts/pseudo_label_w1.py --include-weak --split train --limit 1000 \
  --min-chord-confidence 0.5 --skip-existing --report-every 25 \
  --report ../docs/audit/amt/w1_pseudo_label_full.json
```

`--skip-existing` makes the run resumable; `--offset N --limit M` can split
it into shards. The first 1,000 train candidates are 935 IDMT clips + 65
YouTube weak tracks.

CPU sharding example (4-core machine):

```bash
python scripts/pseudo_label_w1.py ... --offset 0 --limit 500 \
  --report /tmp/w1_main_0_500.json
python scripts/pseudo_label_w1.py ... --offset 500 --limit 250 \
  --report /tmp/w1_shard_500.json
python scripts/pseudo_label_w1.py ... --offset 750 --limit 250 \
  --report /tmp/w1_shard_750.json

python scripts/merge_w1_reports.py \
  --report /tmp/w1_main_0_500.json \
  --report /tmp/w1_shard_500.json \
  --report /tmp/w1_shard_750.json \
  --out ../docs/audit/amt/w1_pseudo_label_full.json
```

The merge deduplicates tracks by id and prefers an actual-run record over an
`existing` skip record.

**Full CPU run result (2026-11-04):** 1,005 selected, **1,004 labeled**,
1 skipped (`idmt_raw:dataset2/audio/AR_Lick6_MN`, `teacher_no_chords`),
**3,309/3,372 windows kept (98.1%)**. Sources: IDMT 934/935, YouTube 70/70.
Final report: `docs/audit/amt/w1_pseudo_label_full.json`. G1’s count gate is
met; the MT3 chord-yield caveat above still motivates W2 teacher selection.
